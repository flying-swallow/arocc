Add src/c3/target.c3, target_data.c3, test/c3/target_tests.c3 and test/migration/target_probe.zig; register //test/c3:target_tests. Source: src/aro/Target.zig Vendor/SubArch, parseArchName/parseOsName/parseAbi, toLLVMTriple, cTypeBitSize/cTypeAlignment, ptrBitWidth, char signedness, bitfield policy, PIC/PIE and dynamic linker helpers. Zig std.Target and std.zig.system are substantive dependencies: inventory every query used here and by Compilation, then port the required rules/data into checked-in C3 data with provenance and licensing. A development-only Zig probe using the pinned reference should serialize target query results for differential testing; production C3 must not invoke Zig. Separate the compiler host from the C program's target, preserving explicit/implicit ABI distinctions and feature/subarchitecture/version handling. Cover the current accepted target space, not only native x86_64; retain unsupported-input errors. Keep target type identities independent of TypeStore internals to avoid a dependency cycle. Acceptance: target tests compare triple parsing, widths/alignments, wchar/long double, endianness and bitfield policy for Linux x86/x86_64, ARM/AArch64, Windows MSVC/MinGW, Darwin, wasm, RISC-V, MIPS and PowerPC, plus all existing Target unit cases and malformed triples. Record exact coverage; no silent native fallback for an unknown target

For every new //test/c3:* target in this ticket, list its .c3 test source files explicitly in project.json. c3c project source entries do not expand `dir/*.c3`; use explicit paths (the source tree may continue to use `src/c3/**`).
